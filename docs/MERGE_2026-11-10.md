## 백업과 동기화 방식

원래 로컬 디렉터리의 `.git`·staged/unstaged 내용·미추적 파일·IDE 설정·빌드 결과물을 모두 포함하는 전체 압축 백업을 만들고 파일 내용까지 검증했습니다. 별도 SHA-256 목록과 staged/unstaged 패치도 보관합니다. 이 백업과 검증 상세 JSON은 사용자의 로컬 작업 결과 폴더에 두며 GitHub에는 올리지 않습니다.

로컬 작업 디렉터리는 이 결과를 담은 `codex/merge-local-swea-20261110` 브랜치로 전환합니다. 원래 master는 백업 가능한 상태로 남기고, 기존 미커밋 파일은 별도 stash에 보존합니다. IDE 메타데이터와 빌드 파일은 로컬에 남기되 Git에서는 제외합니다.

GitHub에는 동일 브랜치를 새로 만들고 master를 대상으로 PR을 엽니다. master를 강제로 갱신하거나 PR을 자동 병합하지 않습니다.

GitHub 플러그인의 트리/브랜치 쓰기는 연결 권한 오류 403(`Resource not accessible by integration`)로 거절되었습니다. 읽기·비교에는 요청한 플러그인을 사용했으며, 브랜치 게시에는 사용자의 기존 Git 로그인을 통한 전송을 시도합니다. PR 생성도 플러그인으로 시도하고 결과를 별도 동기화 기록에 남깁니다.
